Agent Toolkit

One reusable source → many assistants. Stages explain what causes what — not eight colored squares.

01 · Request

Intent lands with constraints: repo context, LLM policy, and desired outcome. Nothing mounts until the request is explicit.

causes → recipe selection

02 · Recipe — pair · team · full

Choose swarm shape. Pair for focused change; team for multi-role delivery; full for broad exploration with observers.

causes → role bindings

03 · Roles

Agents bind to skills (reviewer, planner, implementer, security). Profiles decide which packs install into Cursor, Claude Code, OpenCode.

causes → isolated worktrees

04 · Worktrees

Changes isolate per agent lane. Parallel work stays reviewable; no shared dirty tree by default.

causes → handoffs between roles

05 · Handoffs

Structured transfers: plan → implement → review. Each handoff carries acceptance criteria, not chat residue alone.

causes → durable state

06 · State

Job status, artifact paths, and queue position live outside the model context window — recoverable after restart.

causes → governance checks

07 · Governance

LLM allowlist / strict policy, no silent credential fallback, review gates before merge. Client engagements lock the runner first.

causes → shippable artifact

08 · Artifact

PR, plan.md, review notes, or installed skill pack. The nest’s output is tangible work — not a dashboard of fake progress.
